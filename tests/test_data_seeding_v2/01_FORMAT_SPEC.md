# 01. 테이블정의서 포맷 명세

본 설계의 모든 주제영역 MD 파일은 아래 포맷을 **엄격히** 따른다.
Claude Code 또는 파싱 스크립트가 기계적으로 추출 가능하도록 마크다운 구조를 고정한다.

---

## 1. 파일 상단 (주제영역 전체)

```markdown
# <주제영역 한글명> — 테이블정의서 (<주제코드>)

**주제코드 prefix:** <예: DPG, DPF, DPD 등>
**도메인 약어:** <예: DEP>
**테이블 수:** <총 개수>
**최종갱신:** <YYYY-MM-DD>
**주제영역 범위:** <한 문단 업무 설명>

---
```

## 2. 테이블 단위 블록

각 테이블은 **3개 섹션**으로 구성:
1. 헤더 (ID + 속성 메타)
2. 테이블 설명 (4태그)
3. 컬럼 정의 (행별)

### 2.1 예시 블록

```markdown
## TB_ADW_DPG001M

| 속성 | 값 |
|---|---|
| 테이블명 | TB_ADW_DPG001M |
| 테이블한글명 | DEP_예금계좌기본 |
| 주제영역 | 수신 |
| 도메인 | DEP |
| 유형 | M (Master) |
| 적재주기 | 일배치 |
| 원천시스템 | APB수신원장 |
| 예상건수 | 약 750,000 |

**[테이블 설명]**

```
[엔티티정의]
APB 수신원장과 연계된 예금계좌의 기본정보를 관리한다. 개인·법인의 요구불·저축성 
예금 계좌 단위 마스터로, 신규 개설부터 해지까지의 생애주기를 추적한다.

[대상내]
- 원화 요구불예금 (보통예금, 당좌예금)
- 원화 저축성예금 (정기예금, 자유적금, 정기적금, 주택청약)
- 개인·법인 고객의 계좌 모두

[대상외]
- 외화예금 계좌 (FXC005M에서 별도 관리)
- 퇴직연금 계좌 (RPC003M에서 별도 관리)
- 신탁 계좌 (TRS001M에서 별도 관리)
- 펀드 계좌 (FND001M에서 별도 관리)

[특이사항]
- 해지 후 3년간 보관 (LDGR_SCD='04' 이후 파기 대상)
- 물리삭제 금지. LDGR_SCD='09' 폐기 처리
- 공동명의 계좌는 주명의자 기준으로 CSN 기록, DPG006M에 공동명의 상세 관리
- 약정변경 이력은 DPG002M 에서 별도 버전 관리
```

**[컬럼 정의]**

| # | 컬럼명 | 컬럼한글명 | 타입 | 길이 | Null | PK | [공통정의] | [상세정의] |
|---|---|---|---|---|---|---|---|---|
| 1 | ACN | 계좌번호 | CHAR | 20 | N | Y | 예금계좌를 식별하는 20자리 식별자. 체계: PPP(상품그룹3)+N(13자리난수)+CCCC(체크섬4) | 상동 |
| 2 | CSN | 전산고객번호 | NUMERIC | 10 | N | N | 고객신규 순서에 따라 은행전체적으로 부여됨. 1~1,000,000번은 가상 고객번호임. 1,000,001번 이후가 정상고객임. FK→CSC001M | 상동 |
| 3 | PDN | 상품번호 | VARCHAR | 10 | N | N | 판매 상품 식별자. FK→PFP001M | 상동 |
| 4 | MNGM_BRCD | 관리부점코드 | CHAR | 7 | N | N | 계좌를 관리하는 부점(지점) 코드. FK→CMI001M | 상동 |
| 5 | MNGM_RM_EMN | 관리RM직원번호 | VARCHAR | 10 | Y | N | 고객 담당 RM(Relationship Manager) 직원번호. VIP 고객 위주로 지정됨. FK→CMI003M | 상동 |
| 6 | NEW_YMD | 신규년월일 | CHAR | 8 | N | N | 계좌를 최초 개설한 년월일 (YYYYMMDD) | 상동 |
| 7 | EXPR_YMD | 만기년월일 | CHAR | 8 | Y | N | 계좌의 만기 예정 년월일. 요구불은 NULL. 저축성 만기일. | 만기자동연장 시 본 필드는 갱신되지 않고, DPG002M의 최근 약정 버전에서 확인 |
| 8 | CLS_YMD | 해지년월일 | CHAR | 8 | Y | N | 계좌 해지 실행일. NULL이면 유효 계좌 | 상동 |
| 9 | CLS_CACD | 해지사유코드 | CHAR | 3 | Y | N | 해지 사유. C01:만기정상해지 C02:중도해지-자금필요 C03:중도해지-타행이동 C04:중도해지-금리불만 C05:본인사망 C09:기타 | 상동 |
| 10 | LDGR_SCD | 원장상태코드 | CHAR | 2 | N | N | 원장상태코드 01:정상 02:지급정지 03:압류 04:해지 09:폐기 | 상동 |
| 11 | ETCL_BASE_YMD | ETL기준년월일 | DATE | | N | N | 신규 또는 변경되는 데이터 추출 기준일자 | 상동 |
| 12 | ETCL_JOB_TS | ETL작업일시 | TIMESTAMP | | N | N | 데이터가 신규 또는 변경된 DW의 ETL작업일시 | 상동 |

**[FK 참조]**

- `CSN` → `TB_ADW_CSC001M.CSN`
- `PDN` → `TB_ADW_PFP001M.PDN`
- `MNGM_BRCD` → `TB_ADW_CMI001M.BRCD`
- `MNGM_RM_EMN` → `TB_ADW_CMI003M.EMN` (Nullable)

**[제약/검증]**

- `CLS_YMD IS NOT NULL` ⇒ `LDGR_SCD IN ('04', '09')`
- `EXPR_YMD < NEW_YMD` 금지
- `MNGM_BRCD` 의 `TB_ADW_CMI001M.BR_TCD IN ('40', '50', '90')` 만 허용
  (본점/본부/지역본부 관리는 가상부점 9xxxxxx 통해 우회)

**[쌍둥이/관련 테이블]**

- `TB_ADW_DPG003P` 일별잔액스냅샷 (PK: BASE_YMD + ACN)
- `TB_ADW_DPG004P` 월말잔액스냅샷 (PK: BASE_YM + ACN)
- `TB_ADW_DPG009H` 상태변경이력 (PK: ACN + MDFC_TS)
- `TB_ADW_MRC005S` 고객상품보유현황마트 (CSN 집계)
```

## 3. 태그 체계 규칙

### 3.1 테이블 설명 4태그

| 태그 | 필수여부 | 내용 | 실무 관행 |
|---|---|---|---|
| `[엔티티정의]` | 필수 | 이 엔티티가 무엇인지 1~3문장 | 모든 테이블 작성 |
| `[대상내]` | 선택 | 포함하는 데이터 범위 | 실무에선 30~60% 테이블만 작성 |
| `[대상외]` | 선택 | 명시적으로 제외하는 범위 | 실무에선 20~40% 테이블만 작성 |
| `[특이사항]` | 선택 | 보관 정책/이력 관리/주의점 | 실무에선 40~70% 테이블만 작성 |

**v2 작성 지침:** 70% 테이블은 4태그 모두 작성, 30% 테이블은 일부 태그만(`[대상내]/[대상외]` 빈칸 또는 생략)하여 실 메타의 불완전성 재현.

### 3.2 컬럼 설명 2태그

| 태그 | 필수여부 | 내용 |
|---|---|---|
| `[공통정의]` | 필수 | 컬럼이 표현하는 속성의 일반적 의미 |
| `[상세정의]` | 필수 | 이 테이블 맥락에서의 특수한 의미. `[공통정의]`와 같을 때 `상동` 사용 |

**`상동` 관용어:** 컬럼의 70~80%는 `[상세정의] 상동`으로 기재. 특수 맥락이 있는 20~30%만 상세 기술.

### 3.3 인라인 Enum 표기

코드성 컬럼의 `[공통정의]` 내에 Enum을 직접 기술:

```
[공통정의] 원장상태코드 01:정상 02:지급정지 03:압류 04:해지 09:폐기
```

**혼합 구분자 허용 (실 데이터 불완전성 재현):**
- `01:정상 02:취소` (콜론)
- `1 = 정상, 2 = 취소` (등호)
- `'01' 정상, '02' 취소` (따옴표)

한 도메인코드 내에서 인라인 Enum과 `TB_ADW_CMI008C` 코드테이블이 2% 가량 불일치하도록 의도적 주입.

## 4. 컬럼 표준 패턴

### 4.1 감사 컬럼 (모든 테이블 공통, 항상 마지막 2개)

| 컬럼명 | 한글명 | 타입 | 길이 | Null | 설명 |
|---|---|---|---|---|---|
| ETCL_BASE_YMD | ETL기준년월일 | DATE | - | N | 신규 또는 변경되는 데이터 추출 기준일자 |
| ETCL_JOB_TS | ETL작업일시 | TIMESTAMP | - | N | 데이터가 신규 또는 변경된 DW의 ETL작업일시 |

일부 테이블(7~10%)에만 추가 감사 컬럼:
- `ETCL_SRCE_ID` VARCHAR(20) — 원천시스템 식별자
- `LAST_MDFC_EMN` VARCHAR(10) — 최종변경자

### 4.2 전형적 PK 패턴

| 테이블 유형 | PK 패턴 | 예시 |
|---|---|---|
| 마스터 (M) | 엔티티 식별자 단일 | `ACN`, `CDN`, `EMN` |
| 일별 스냅샷 (P) | 날짜 + 엔티티 | `BASE_YMD + ACN` |
| 월별 집계 (S) | 월 + 엔티티 | `BASE_YM + ACN` |
| 이력 (H) | 엔티티 + 변경시점 | `ACN + MDFC_TS` |
| 거래 (L) | 거래번호 단일 | `TRN_NO` |
| 코드 (C) | 도메인코드 + 코드 | `DMCD + CD` |
| 상세 (D/T) | 헤더번호 + 순번 | `SLN + SQN` |

### 4.3 FK 명명 규칙

- 외래키 컬럼명은 참조 테이블의 PK 컬럼명과 동일하게 유지
  - `CSN`은 어느 테이블이든 고객번호
  - `BRCD`는 어느 테이블이든 부점코드
  - `LON_ACN`은 어느 테이블이든 대출계좌번호

- **단, 의미 다른 동명 컬럼 주의** (실무 함정 재현):
  - `TB_ADW_LNB013M.GRNT_CSN` = 보증인 고객번호 (차주 CSN과 다름)
  - `TB_ADW_CSC008M.RLTD_CSN` = 관련인 고객번호

## 5. 타입 체계

### 5.1 허용 타입

| 타입 | 용도 |
|---|---|
| `CHAR(n)` | 고정길이 문자. 코드/식별자 (예: BRCD 7, LDGR_SCD 2) |
| `VARCHAR(n)` | 가변 문자. 이름/주소/설명 |
| `NUMERIC(p, s)` | 정밀 숫자. 금액/금리 (예: `NUMERIC(18,2)` 금액, `NUMERIC(10,6)` 금리) |
| `INT` | 정수. 건수/횟수 |
| `DATE` | 날짜 단독 (드뭄, 대부분 CHAR(8) YYYYMMDD 사용) |
| `TIMESTAMP` | 일시 |

### 5.2 관행

- 날짜는 `CHAR(8)` YYYYMMDD 포맷 사용이 기본 (정보계 관행)
- 시각은 `CHAR(6)` HHMMSS 또는 `TIMESTAMP`
- 금액은 `NUMERIC(18, 2)` (원화 최대 18자리, 소수 2자리)
- 외화금액도 `NUMERIC(18, 2)`
- 금리는 `NUMERIC(10, 6)` (예: 3.750000)
- 비율/지분은 `NUMERIC(5, 2)` (예: 100.00%까지)
- 환율은 `NUMERIC(14, 6)`

## 7. 의도적 결함 주입 지침 (실무 재현)

### 7.1 `[상세정의] 상동` 분포

- **70%** 컬럼: `[상세정의] 상동`
- **20%** 컬럼: `[상세정의]` 별도 문장 (상세 해설)
- **10%** 컬럼: `[상세정의]` 자체 누락 (또는 빈 문자열)

### 7.2 태그 누락 분포

- 테이블의 30%: `[대상내]` 또는 `[대상외]` 비어있음
- 테이블의 20%: `[특이사항]` 비어있음

### 7.3 명명규칙 위반 소수 (레거시 표현)

- 5~10개 테이블: `TB_ADW_LNX###*` 같이 구 주제코드 잔존 (`LNX`는 과거 여신 코드)
- 2~3개 테이블: 유형코드 없이 숫자만 (예: `TB_ADW_DPGETC01`) — 특수 사유 테이블

### 7.4 쌍둥이 테이블 의도적 중복

주요 엔티티의 일별/월별/이력/거래 유형을 모두 생성:

| 엔티티 | P (일별) | S (월별) | H (이력) | L (거래) |
|---|---|---|---|---|
| 예금계좌 | `DPG003P` | `DPG004P` | `DPG009H` | `DPG005L` |
| 대출계좌 | `LNB003P` | `LNB004P` | `LNB009H` | `LNB005L` |
| 카드 | - | `SLE005S` (청구) | `CLN005H` (한도) | `SLE001T` |
| 외화예금 | `FXD003P` | `FXD004P` | - | `FXD005L` |

**NL-to-SQL 쌍둥이 함정:** "지난달 예금 잔액"은 DPG004P 또는 MVP014S 둘 다 맞을 수 있음. 맥락 따라 구분 필요.

## 8. 파싱 편의를 위한 규칙

- 모든 테이블 블록은 `## TB_ADW_` 로 시작 (h2 헤더)
- 속성 메타 표는 반드시 `| 속성 | 값 |` 형식 첫 컬럼 고정
- 테이블 설명은 반드시 ```` ```...``` ```` 펜스 블록 내
- 컬럼 정의 표는 반드시 10열 (`# | 컬럼명 | ... | [상세정의]`)
- FK 참조는 bullet `-` 리스트, `→` 화살표 사용

이 규칙을 지키면 단일 regex/parser로 1,441개 테이블을 구조화된 JSON으로 변환 가능.
