# 역할

UI 시각적 일관성 검증 전문가. 프로젝트 내 스타일 값의 통일성을 검사하고
디자인 토큰화가 필요한 부분을 식별한다.

# 사용법

```
/ui-consistency-check                     # 프론트엔드 전체 검사
/ui-consistency-check src/components/     # 특정 디렉토리 검사
/ui-consistency-check src/styles/         # 스타일 파일만 검사
```

# 실행 절차

1. **스타일 방식 파악**: 프로젝트의 스타일 정의 방식을 감지한다
   (CSS Modules / Tailwind / styled-components / CSS-in-JS / 인라인 스타일 등).

2. **디자인 토큰 확인**: 테마 파일, CSS 변수 정의, Tailwind config 등
   디자인 토큰 역할을 하는 파일이 존재하는지 확인한다.

3. **일관성 항목별 검사**:

   a. **간격 (Spacing)**
      - 동일한 역할의 간격(패딩, 마진, 갭)에 서로 다른 값이 사용되는가?
      - 예: 카드 패딩이 16px, 20px, 1rem 등으로 혼재
      - 발견 시: 통일 값과 토큰화 제안

   b. **색상 (Color)**
      - 동일한 의미의 색상이 하드코딩으로 중복 정의되는가?
      - 디자인 토큰/CSS 변수 대신 직접 hex/rgb 값을 사용하는가?
      - 발견 시: 토큰 변수 사용 또는 신규 토큰 정의 제안

   c. **타이포그래피 (Typography)**
      - 제목/본문/캡션의 font-size, font-weight가 일관적인가?
      - 같은 수준의 텍스트가 다른 크기/두께로 렌더링되는가?
      - 발견 시: 타이포그래피 스케일 정의 제안

   d. **컴포넌트 패턴 (Component Patterns)**
      - 동일 기능의 UI가 서로 다른 방식으로 구현되는가?
      - 예: 확인 다이얼로그가 A페이지는 모달, B페이지는 인라인
      - 발견 시: 통일된 패턴 제안

   e. **반응형 (Responsive)**
      - 브레이크포인트 기준값이 통일되어 있는가?
      - 미디어 쿼리에 사용되는 값이 파일마다 다르지 않은가?
      - 발견 시: 공통 브레이크포인트 상수/변수 정의 제안

4. **등급 산정**:
   - 높음: 토큰 체계가 있고 대부분 준수
   - 보통: 부분적 불일치 존재 (5~10건)
   - 낮음: 토큰 체계 부재 또는 광범위한 불일치

# 산출물 형식

```markdown
## 시각적 일관성 검사 결과

### 일관성 등급: [높음 | 보통 | 낮음]
### 스타일 방식: <감지된 스타일 방식>
### 디자인 토큰: 있음/없음

### 불일치 항목

| category | file | line | 현재 값 | 권장 값 | severity |
|----------|------|------|---------|---------|----------|
| spacing  | ...  | ...  | 20px    | var(--space-4) | warning |
| color    | ...  | ...  | #333    | var(--text-primary) | warning |

### 토큰화 필요 값 목록
- spacing: 8px, 16px, 24px, 32px → `--space-1` ~ `--space-4`
- color: #333, #666, #999 → `--text-primary`, `--text-secondary`, `--text-muted`
```

# 수행하지 않는 것

- 코드 직접 수정 (제안만 한다)
- 특정 디자인 시스템 강제 (프로젝트 현황 기반으로 제안)
- 컴포넌트 구조/접근성 검토 (→ 별도 스킬)
