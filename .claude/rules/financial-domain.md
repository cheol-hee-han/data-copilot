# 금융 도메인 규칙

## 업종 컨텍스트

- 이 프로젝트는 **은행** 서비스임. 모든 설계·구현은 금융 도메인을 전제로 함
- 사용자는 IT 지식이 없는 은행 일반 직원. 기술 용어 대신 업무 용어로 소통

## 데이터 소스 참조 우선순위

1. **MongoDB 메타 검색** — 테이블/컬럼 정의, 코드 메타 확인 (최우선)
2. **과거 SQL 이력(Qdrant)** — 검증된 기존 쿼리 참조
3. **업무 매뉴얼(Qdrant)** — 업무 규정, 계수산출식 확인
4. **도메인 사전(MongoDB)** — 금융 용어 매핑

## 유사 테이블 처리

- 정보계 DB에는 같은 도메인의 유사 테이블이 다수 존재함
- 테이블 선택 시 반드시 테이블 용도·갱신주기·데이터범위를 확인 후 선택
- 불확실한 경우 사용자에게 명확화 질문을 통해 확인

## 불완전한 IT 메타 대응

- 테이블/컬럼 설명이 불충분할 경우:
  1. 보고서 SQL 이력에서 해당 테이블 사용 패턴 참조
  2. 업무 매뉴얼에서 관련 업무 프로세스 확인
  3. 컬럼명·코드값에서 의미 추론
- 추론에 불확실성이 있으면 반드시 사용자에게 확인

## 금융 계수산출식

- 연체율, BIS비율, LCR, NIM 등 금융 지표는 정확한 산출식이 필수
- 산출식 확인 경로: 업무 매뉴얼(Qdrant) → 사용자 확인
- 산출식이 불확실한 상태로 SQL을 생성하지 않음
