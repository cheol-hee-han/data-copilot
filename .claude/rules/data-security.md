# 데이터 보안 규칙

## SQL 생성 제약

- SELECT 문만 허용. INSERT/UPDATE/DELETE/DROP/TRUNCATE/ALTER 등 절대 금지
- 다중 쿼리(세미콜론 연쇄) 금지
- 시스템 카탈로그(information_schema, pg_*) 접근 금지
- 읽기 전용 DB 계정만 사용

## 개인정보 보호 (금융 PII)

- 직접 노출 금지 컬럼: 주민등록번호, 계좌번호, 카드번호, 비밀번호, CVC
- 필수 마스킹 컬럼: 전화번호, 이메일, 생년월일, 주소
- 고객명은 용도에 따라 마스킹 여부 결정 (목록 조회 시 부분 마스킹)
- 개인신용정보는 최소 권한 원칙 적용

## 대용량 데이터 보호

- 결과 행 수 제한: 기본 10,000건 (사용자 요청 시 상향 가능)
- 전체 테이블 덤프 성격의 요청은 거부하고 조건 추가 유도
- 대용량 테이블(이벤트 로그 등)에는 반드시 날짜 조건 + LIMIT 적용

## 프롬프트 인젝션 방어

- 사용자 입력에서 시스템 프롬프트 우회 시도 감지
- SQL 키워드가 포함된 자연어 입력은 의도 확인 후 처리
- LLM 응답에서 SQL 외 실행 가능한 코드 필터링

## 감사 추적

- 모든 SQL 생성·실행 이력 로깅 (사용자ID, 질의, 생성SQL, 실행시간)
- 로그에 개인정보 포함 금지 (마스킹 후 로깅)
