## 슬롯 1: INTENT — 질의 유형
────────────────────────────────
질의의 핵심목적(primary)과 수단(secondary)을 분류합니다. 
primary는 반드시 1개, secondary는 0개 이상입니다.

허용값:
- EXTRACT     : 단순 목록/리스트 조회. 행 단위 결과. 집계 없음.
                시그널: "목록", "리스트", "뽑아줘", "조회", "알려줘", "보여줘", "어디", "누구"
- AGGREGATE   : 집계 연산이 포함된 조회. GROUP BY 필요.
                시그널: "합계", "총", "평균", "건수", "~별 ~"
- COMPARE     : 두 집합/기간 간 비교. 셀프조인이나 서브쿼리 필요.
                시그널: "대비", "비교", "vs", "차이", "동기대비", "YoY", "MoM"
- TREND       : 시간 축 따른 변화 패턴. 시계열 분석.
                시그널: "추이", "변화", "증감추세", "트렌드", "성장"
- RANK        : 순위 기반 결과 필요.
                시그널: "상위", "하위", "top", "bottom", "순위", "1위", "N번째"
- DISTRIBUTE  : 분포/비율/점유율 분석.
                시그널: "분포", "비율", "점유율", "비중", "구성비", "퍼센트"
- EXIST_CHECK : 존재 여부 확인.
                시그널: "~있는지", "~한 적", "~이력이 없는", "~여부"
- DEDUP       : 중복 관련 조회.
                시그널: "중복", "겹치는", "유니크", "고유"
- PIVOT       : 교차 분석.
                시그널: "크로스탭", "교차", "매트릭스"

INTENT 판별 절차:

Step 1 — 후보 감지 및 primary 결정
아래 질문을 Q1부터 순서대로 적용한다.
※ 시그널 키워드가 존재하지만, 질의의 "행위/목적"이 아니라 "데이터 항목명"이나 수식어
   또는 "엔티티명"으로 쓰인 것으로 판단되는 경우 해당 질문은 NO로 판정한다.
   예: "변화량 TOP 3" → "변화"는 데이터 항목명의 일부이므로 TREND 아님
       "비교적 큰 금액" → "비교"가 수식어의 의미로 사용된 것으로 COMPARE 아님

  Q1. "대비/비교/vs/YoY/MoM" 등으로 두 시점·집합을 비교하는가?  → COMPARE
  Q2. "추이/변화/트렌드/성장" 등으로 시간 축 변화를 보는가?      → TREND
  Q3. "상위/하위/top/bottom/N위" 등으로 순위를 추리는가?        → RANK
  Q4. "비율/비중/분포/점유율/구성비" 등으로 분포를 구하는가?      → DISTRIBUTE
  Q5. "교차/크로스탭/매트릭스" 등으로 교차 분석하는가?           → PIVOT
  Q6. "~별" + 집계 지표(합계/평균/건수)로 집계 결과를 보는가?    → AGGREGATE
  Q7. 위 어디에도 해당하지 않는다                              → EXTRACT

  → 처음 YES인 것이 primary

Step 2 — secondary 보충
  - primary 외에 YES였던 항목 → secondary에 추가
  - "~별" + 집계 표현이 있으나 Q6에서 누락된 경우 → AGGREGATE를 secondary에 반드시 포함
  - EXIST_CHECK, DEDUP 시그널이 있으면 → 별도로 추가

## 슬롯 2: ENTITY — 대상 엔티티
────────────────────────────────
type 허용값: DIRECT, INDIRECT, IMPLIED

추출 규칙:
1. 명사 중 데이터 테이블이 될 수 있는 것을 모두 추출
2. 측정값(잔액, 건수 등)은 ENTITY가 아닌 MEASURE로 분류
3. "~의", "~에 대한" 뒤에 오는 명사도 엔티티 후보
4. 질의 수행에 필요하지만 명시되지 않은 엔티티는 IMPLIED로 추가
5. 은행 도메인 엔티티: 고객, 계좌, 대출(여신), 예금(수신), 거래, 카드, 지점, 직원, 상품, 담보

## 슬롯 3: MEASURE — 측정값/지표
────────────────────────────────
measure_type 허용값: RAW, DERIVED, RATIO, WINDOW
agg_function 허용값: SUM, AVG, COUNT, COUNT_DISTINCT, MAX, MIN, NONE, UNKNOWN

추출 규칙:
1. DIMENSION("~별")이 존재하면 MEASURE의 agg_function은 NONE이 될 수 없음
2. "실적", "성과", "신규", "현황" 등 2가지 이상 해석이 가능한 지표는 ambiguities에 기재
3. 계산식이 필요한 파생 지표(연체율, NIM 등)는 measure_type=DERIVED로 표시
4. 금융 지표(연체율, BIS비율, LCR, NIM, ROA, ROE)는 정확한 산출식이 필수 → note에 기재
5. agg_function을 확정할 수 없으면 'UNKNOWN'으로 두고, 반드시 ambiguities에 기재

## 슬롯 4: DIMENSION — 분류/그룹 축
────────────────────────────────
role 허용값: GROUP, PARTITION, FILTER, DISPLAY

granularity 허용값 (시간 차원): YEAR, QUARTER, MONTH, WEEK, DAY, HOUR, UNKNOWN
granularity 허용값 (비시간 차원): INDIVIDUAL, CATEGORY, HIERARCHY, UNKNOWN
is_time_dimension: 시간 관련 차원이면 true

추출 규칙:
1. "~별", "~기준", "~단위로", "~마다", "각 ~" → GROUP role
2. "~ 내에서 순위" → PARTITION role
3. 하나의 표현에 복수 차원이 중첩될 수 있음

## 슬롯 5: FILTER — 조건
────────────────────────────────
filter_type 허용값:
EQUALS, NOT_EQUALS, IN, NOT_IN, RANGE, GT, GTE, LT, LTE,
LIKE, IS_NULL, IS_NOT_NULL, EXISTS, NOT_EXISTS, IMPLICIT

position 허용값: PRE_AGG (WHERE), POST_AGG (HAVING)

추출 규칙:
1. "~만", "~에 해당하는" → EQUALS 또는 IN
2. "~제외", "~빼고" → NOT_EQUALS 또는 NOT_IN
3. "~이상/초과/이하/미만" → GTE/GT/LTE/LT
4. MEASURE에 대한 조건 + DIMENSION 함께 → POST_AGG
5. "정상 계좌", "활성 고객" → IMPLICIT + note에 비즈니스 규칙 기재

2. "현황", "요약", "개요" → format=SUMMARY
3. "상세", "전체", "전건" → format=DETAIL_LIST

해당 업무 도메인에서 일반적으로 기대되는 컬럼명을 추론하여 expected_columns에 채우세요.

## 추가 출력 필드
────────────────────────────────
rewritten_query: 확정 가능한 부분만 재작성한 한국어 질의.
  - 원문의 의미를 보존하되, 확정 가능한 암시적 내용만 명시적으로 풀어씀
  - 모호한 부분은 원문 표현 그대로 유지 ("~로 해석", "~를 의미함" 같은 추측 포함 금지)
  - output_hint가 있으면 기대 컬럼을 포함하여 재작성

search_keywords:
  - meta_search: 테이블/컬럼 메타 검색에 사용할 키워드 (엔티티+측정값 중심)
    ※ output_hint.expected_columns의 컬럼명도 여기에 포함시키세요.
  - vector_search: 유사 SQL 사례를 검색할 의도 요약 문장 (1문장)

ambiguities: 질의에서 발견된 모호성에 대한 구조화된 판단 정보 배열.
정규화 시점에는 메타/SQL 이력이 없으므로, 모호한 부분을 사용자에게 묻지 않고
업무 관행·문맥을 기반으로 **최선의 해석을 추론(INFER)**하여 기록한다.
이후 Reason 계층에서 메타 탐색 시 검증 포인트로 활용된다.
  - ambiguity_type:
    INTENT — 용어 해석·집계 기준 모호 (동일 용어가 2가지 이상 해석 가능, 집계 기준 불명확)
    TIMEFRAME — 기간·시점 모호 (기간 조건이 2가지 이상 해석 가능)
  - ambiguities 판단 체크리스트 — 다음 중 하나라도 해당하면 ambiguities에 기재
    INTENT — 동일 용어가 2가지 이상 해석 가능
             예: "신규" → 신규 개설 건수 / 신규 유입 금액 / 신규 가입 고객 수
             예: "이체" → 이체 건수 / 이체 금액
             예: "잔액" → 평균잔액 / 기말잔액 / 최저잔액
    INTENT — 집계 기준이 불명확
             예: "상위" → 금액 기준 상위 / 건수 기준 상위
             예: "많은" → 금액이 많은 / 건수가 많은
    TIMEFRAME: 기간 조건이 2가지 이상 해석 가능
             예: "최근" → 최근 1개월 / 최근 분기 / 최근 1년
