# AI 에이전트 서비스 요구사항 작성 파일입니다.

아래의 요구사항을 가진 AI 에이전트 서비스를 구현하려고 해

 1. 해당 에이전트의 UI 인터페이스는 챗봇 형태로 구현되어 
 2. 다양한 사용자의 자연어로 된 데이터 추출/분석 요청을 입력으로 받아 
 3. 해당 입력에 대한 의미를 분석하고(함의 파악, 구조화, 정규화 등)
 4. 사내 다양한 플랫폼에 있는 관련 참조 정보를 바탕으로 데이터 추출/분석 방법을 추론하여 
 5. 데이터 추출을 위한 SQL을 작성하여 데이터를 추출하거나
 6. 데이터 분석이 목적이라면 데이터와, 데이터 기반 분석 결과를 요청자에게 리턴
 7. 만약 추론 과정에서 모호한 점이 있는 경우 사용자에게 추가 질문을 하여 요구사항을 명확히 하는 과정을 거침
 8. 사용자는 IT 관련 지식이 없는 일반 직원이 될 수 있기 때문에, 최대한 친절하고 이해하기 쉬운 방식으로 결과를 제공해야 함
 9. 데이터 분석 결과를 시각화해서 보여주는 것이 더 낫다고 판단되는 경우, 클로드 처럼 로컬 LLM이 직접 판단하여 SVG/HTML 코드를 직접 생성하도록 유도하고, 생성된 코드를 프론트엔드에서 다양하게 렌더링 할 수 있도록 지원

참고 1. 사내 참조 가능한 정보 (저장소별)
  <Qdrant Vector Store>
   - 은행 모든 상품에 대한 설명이 담긴 상품설명서(텍스트 자체를 임베딩, 상품에 대한 소비자용 설명으로 SQL 추론에 필요한 직접적인 힌트는 아님)
   - 업무수행 절차와 설명 등이 담기 업무매뉴얼(텍스트 자체를 임베딩, 일반적인 업무매뉴얼로 SQL 추론에 필요한 직접적인 힌트는 아님)
   - 과거 수행된 SQL과 설명(설명으로 임베딩)
  <MongoDB>
   - 테이블 및 컬럼 레이아웃과 설명정보, 주제영역 포함
   - 코드 메타 정보
   - 비즈용어 사전(정의된 용어가 200개 이내로 다소 부실)
  <추가구현검토중,현재없음>
  - 프로그램 코드가 저장된 프로그램 저장소
  - 기존 보고서팀에서 작성한 보고서 SQL과 보고서 요건 정보가 저장된 저장소
  - SQL 골든셋(아직 없음, 구현방안 미정)

참고 2. 업무 도메인
  - 기본적으로 우리 회사는 은행이기 떄문에 금융 관련 업무 도메인 지식이 가장 중요하고
  - 금융 업무 도메인에서 발생하는 다양한 서브 업무 도메인에 대해 각 도메인별로 특화된 데이터 추출/분석 방법을 적용할 수 있어야 함

참고 3. 도전 과제
  - 다양한 사용자의 자연어 입력을 정확히 이해하고, 그에 맞는 데이터 추출/분석 방법을 추론하는 것은 매우 어려운 문제임
  - 특히 금융 업무 도메인에서는 전문 용어와 복잡한 업무 프로세스가 존재하기 때문에, 이를 정확히 파악하는 것이 중요함
  - 또한 행내에는 참고할 테이블/컬럼 설명(IT메타)이나 SQL에 대한 주석 등이 충분히 상세하지 않은 경우가 많아, 이를 보완하기 위한 추가적인 정보 추출, 추론 노하우 적용이 필요할 수 있음
  - 특히, 테이블은 사용하기 전에 테이블 내 어떤 데이터가 있는지(엔티티 집합 정의), 데이터는 어디에 어떻게 쓰이는지(기능적 정의), 데이터는 언제 생성되어 적재되는지(데이터 발생규칙) 세 가지의 측면에서 추론하는 것이 필요함
  - 그리고 데이터를 추출하는 DB 는 정보계 DB로 유사 도메인의 테이블이 많이 존재하기 때문에, 해당 요구사항에 맞는 정확한 테이블과 컬럼을 선택하는 것도 중요한 문제임
  - 업무매뉴얼에 포함되지 않은 디테일한 계수산출식 등이 필요할 수 있는데 이에 대한 추론 시 아이디어가 필요할 수 있음
  - 마지막으로, 추출된 데이터가 요청된 요구사항에 부합하는지 정합성 검증 방법을 추론하는 것도 중요한 문제임

참고 4. 기술적 요구사항
  - Python 3.11 ~ 3.12 버전을 사용하여 구현
  - LangGraph 라이브러리를 활용하여 자연어 처리 및 데이터 추출/분석 로직 구현
  - MongoDB, PostgreSQL, Qdrant Vector Store, Neo4j 등 사내 다양한 플랫폼과의 연동을 위한 API 개발 (2026-04 ES 제거)
  - API는 온라인 구현 후 폐쇄망에 배포될 예정이므로, 설정파일 변경만으로 폐쇄망에서도 원활히 작동할 수 있도록 설계
  - 사용자 인터페이스는 챗봇 형태로 구현하여, 사용자가 자연어로 요청을 입력할 수 있도록 설계
  - 실제 데이터를 조회할 타겟 DB는 정보계 DB인 sybase iq 와 빅데이터 플랫폼(cloudera)의 impala DB(LDAP login)가 될 예정이며, 해당 DB와의 연동을 위한 SQL 작성 및 실행 로직 구현
  - 폐쇄망에서 사용할 AI 모델은 추론 가능한 중대형 오픈소스 LLM (현재: Solar Pro 2 70B, 업그레이드 예정: Qwen3.5 397B 또는 GPT OSS 120B). Claude/GPT-4 대비 성능 차이를 고려한 프롬프트 설계 필요
  - 사용자가 "왜 이 테이블을 골랐는지", "왜 이 SQL을 생성했는지", "정합성을 위해 뭘 검증했는지", "검증에서 뭘 고쳤는지" 등 추론 과정에 대한 설명을 요청할 수 있기 때문에, 추론 과정과 주요 의사결정에 대한 설명 생성 로직도 함께 구현 필요(파이프라인 추론 추적 기능)
  - 만약 분석결과 시각화 관련 기능 구현이 필요한 경우, React + Vite + TypeScript + FastAPI 조합으로 프론트엔드와 백엔드 API를 구현하는 것을 제안


LangGraph 추적 기능 활용하여, 추론 과정에서 어떤 정보가 참조되었는지, 어떤 의사결정이 내려졌는지 등을 기록하고, 
이를 바탕으로 사용자가 요청할 때 설명을 제공할 수 있도록 구현 필요.

  - 노드 시작/종료 기록 추적
  - 노드 흐름 로깅
  - LLM 호출 기록 추적 (in/out 정보, 시작/종료 시각 포함)
  - LLM 호출 output 파싱 및 의도 트래킹
  - Tool 호출 기록 추적 (in/out 정보, 시작/종료 시각 포함)
  - state 변화 기록 추적 (눈으로 추적에 용이한 방식 제안) 
  - 개별 노드에서 추가적으로 트래킹 해야 하는 항목 별도 트래킹 (로직 기반)
  - WebSocket 진행상황 전파 (현재노드, 요약정보, 또는 스트리밍)
  - 최종적으로, 통합 타임라인 보고서를 구현 
    1) 전체 흐름을 시작부터 끝까지 순번 + 부모-자식 관계로 단일 타임라인에 기록, 최종적으로 Mermaid 다이어그램으로 표현하여 시각적 분석 지원
    2) 타임라인 보고서에는 각 단계별로 참조된 정보, 내려진 의사결정, state 변화, 생성된 SQL 등이 포함되어야 함
    3) 타임라인 보고서는 사용자가 요청할 때마다 자동으로 생성되어 제공될 수 있도록 구현 필요
