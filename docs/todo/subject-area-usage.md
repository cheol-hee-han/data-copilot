# TODO — 주제영역(subject_area) 활용 검토

## 배경

MongoDB `dpasset_table`에 `schema_name` 필드가 있지만, 현재는 주제영역으로 활용되지 않는다.
테이블 메타 검색 시 `$text`로 키워드 매칭만 수행하여, 유사 도메인 테이블이 다수 후보로 올라온다.

예: "여신 잔액"으로 검색 시 → 여신_잔액, 여신_실행, 여신_기본 등 여러 주제영역 테이블이 혼재.

## 핵심 판단: 필터링이 아닌 랭킹에 활용해야 함

주제영역을 **필터링 조건으로 사용하면 안 된다.**
조인이 필요한 질의에서 다른 주제영역의 테이블을 탈락시키는 부작용이 발생하기 때문이다.

```
"VIP 고객의 지점별 여신 연체 현황"

필요 테이블:
  TB_CUST_INFO    (고객_기본)     ← 고객 등급 필터
  TB_LN_BAL_D     (여신_잔액)     ← 잔액 + 연체 데이터
  TB_BRANCH_M     (조직_기본)     ← 지점 그룹핑

→ 3개 주제영역에 걸쳐 조인 필요
→ 주제영역으로 필터링하면 TB_CUST_INFO, TB_BRANCH_M 탈락
```

**올바른 활용 방식**: 후보가 과다할 때 같은 영역끼리 묶어서 **우선순위 점수 조정**에 사용.
ENTITY+MEASURE와 매칭되는 주제영역 테이블에 높은 점수, 다른 영역은 낮은 점수로 유지하되 **제거하지 않음**.
