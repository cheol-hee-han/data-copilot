# 04. 업무 상태 전이·시계열·계절성 패턴

> 금융 데이터는 시간에 따라 일정한 패턴을 가진다.
> 급여일, 분기말, 결산기, 금리 변동 시기에 따라 데이터의 양과 분포가 달라진다.
> 또한 각 업무 엔티티는 명확한 상태 전이 규칙을 가진다.

---

## 1. 상태 전이 다이어그램 (State Machine)

### 1.1 대출 생애주기

```
[신청접수] → [심사중] → [승인] → [실행(정상)] → [완제(해지)]
                │                      │
                ↓                      ↓
             [반려]               [연체발생]
                                       │
                                       ↓
                            [단기연체(1~29일)]
                                       │
                              ┌────────┴────────┐
                              ↓                  ↓
                         [정상회복]        [장기연체(30~89일)]
                                                 │
                                        ┌────────┴────────┐
                                        ↓                  ↓
                                   [정상회복]        [부실(90일+)]
                                                          │
                                                ┌─────────┼─────────┐
                                                ↓         ↓         ↓
                                           [채무재조정] [대위변제] [매각/상각]
```

**전이 확률 (현실적 비율):**
```
정상 → 단기연체:        월 0.5~1.0%
단기연체 → 정상회복:    70~80%
단기연체 → 장기연체:    20~30%
장기연체 → 정상회복:    30~40%
장기연체 → 부실:        60~70%
부실 → 채무재조정:      20%
부실 → 대위변제:        30% (보증대출)
부실 → 매각/상각:       50%
```

### 1.2 예금 계좌 생애주기

```
[개설] → [정상(활성)] → [해지]
               │
               ↓
        [거래 미발생 1년+]
               │
               ↓
          [휴면 전환] → [재활성화(입금 발생)] → [정상]
               │
               ↓
          [해지(장기 미활동)]
```

**전이 확률:**
```
정상 → 휴면:            연 5~8% (1년 이상 미거래)
휴면 → 재활성화:        연 10~15%
휴면 → 해지:            연 3~5%
정상 → 해지(고객 요청):  연 8~12%

특수:
정기예금 만기 → 자동연장(60%) / 해지(30%) / 보통예금 전환(10%)
적금 만기 → 해지+보통예금 입금(80%) / 정기예금 전환(20%)
```

### 1.3 고객 등급 전이

```
         ┌─────── [VIP] ←─────┐
         │           │         │
         │     (자산 감소)  (자산 증가)
         ↓           ↓         │
     [VIP 유지]  [Gold] ──────┘
                     │
               (자산 감소)
                     ↓
                 [Silver]
                     │
               (자산 감소)
                     ↓
                [General]
```

**전이 확률 (분기별 평가):**
```
VIP → VIP:       85%    (대부분 유지)
VIP → Gold:      14%    (하락은 점진적)
VIP → Silver:     1%    (두 단계 이상 하락은 드묾)

Gold → VIP:       8%    (승급)
Gold → Gold:     80%
Gold → Silver:   12%

Silver → Gold:    5%
Silver → Silver: 82%
Silver → General:13%

General → Silver:  3%
General → General:97%   (상위 등급 진입 어려움)
```

### 1.4 연체 독촉 단계 전이

```
[연체 발생] → [SMS 통보(D+1)] → [전화 독촉(D+7)] → [내용증명(D+30)] → [법적조치(D+90)]
```

**시간 규칙:**
- SMS 통보: 연체 발생 익일 자동 발송
- 전화 독촉: 연체 7일 차부터 시작, 주 2회
- 내용증명: 30일 이상 연체 시 1회 발송
- 법적조치: 90일 이상 연체 + 금액 1,000만원 이상

## 2. 시계열 패턴 — 일별/주별/월별

### 2.1 일중(日中) 패턴

```
시간대별 거래 건수 분포:

00~06시:  전체의  2%  (새벽 — 배치 처리, 해외 거래)
06~09시:  전체의  5%  (출근 전 — 모바일 조회·이체)
09~10시:  전체의 15%  ★ 영업점 개시 + 기업 자금이동 집중
10~12시:  전체의 20%  ★ 오전 업무 피크
12~13시:  전체의  5%  (점심시간 — 소액 이체)
13~16시:  전체의 25%  ★ 오후 업무 피크
16~17시:  전체의 15%  ★ 마감 직전 집중
17~18시:  전체의  8%  (퇴근 시간 — 모바일)
18~24시:  전체의  5%  (저녁 — 소액, 모바일)
```

**시드 데이터 반영:**
- TB_TRANSACTION.TXN_TM을 위 분포에 맞게 생성
- 기업거래: 09~17시 집중 (99%)
- 개인거래: 07~22시 분산

### 2.2 요일별 패턴

```
월요일:  전체의 18%  ★ 주말 밀린 거래 처리
화요일:  전체의 17%
수요일:  전체의 16%
목요일:  전체의 16%
금요일:  전체의 18%  ★ 주말 대비 자금 이동
토요일:  전체의  9%  (ATM·모바일만)
일요일:  전체의  6%  (모바일만)
```

### 2.3 월중(月中) 패턴

```
매월 특이일:

1일:     공과금 자동이체 집중 (평소의 3배)
5일:     카드대금 결제일 (일부 카드사)
10일:    국민연금·건강보험 납부
14일:    카드대금 결제일 (일부 카드사)
15일:    중간 정산, 일부 기업 급여일
20일:    각종 보험료 납부
25일:    ★★★ 급여일 — 입금 거래 폭증 (평소의 5~8배)
          급여 입금 후 즉시 이체·출금 다수
26~28일: 급여 후 소비 지출 (카드, 이체)
말일:     대출이자 납부, 월말 자금 정리, 적금 납입

# 시드 데이터에서 TXN_DT의 일(day) 분포를 위 패턴에 맞게 조절
```

### 2.4 월별(연간) 계절성

```
1월:   ▼ 대출 신규 감소 (연말 집중 후 반동)
       ▲ 정기예금 만기 도래 (전년 1월 가입분)
       연초 효과: 적금 신규 증가

2월:   ▼ 영업일수 적어 거래 감소
       설 연휴 전후: ATM 출금 급증, 이체 감소

3월:   ▲ 신학기 — 학자금대출 증가, 전세자금대출 증가
       ▲ 봄 이사철 시작 — 주택담보대출 증가

4~5월: ▲ 봄 이사철 피크 — 주택 관련 대출 최고치
       ▲ 거래량 평균적

6월:   ▲ 상반기 실적 마감 — 지점 영업 강화
       ▲ 정기예금 유치 경쟁 (금리 우대 이벤트)
       분기말: 기업 자금이동 활발

7~8월: ▼ 여름 휴가 — 거래 소폭 감소
       ▲ 하반기 신규 상품 출시

9월:   ▲ 가을 이사철 — 전세/주택대출 재증가
       분기말: 기업 자금이동

10~11월: ▲ 연말 실적 달성 압박 — 대출 실행 증가
         ▲ 연말정산 대비 IRP·연금 납입 증가

12월:  ★ 연말 — 대출 실행 최대 (실적 마감)
       ★ 정기예금 만기 자금 재예치
       ★ 상여금 입금 → 정기예금 가입 증가
       ★ 연말 보너스 + 성과급 입금
       ▲ IRP 납입 마감 (세액공제)
```

**시드 데이터 반영 방법:**
```python
# 월별 대출 실행 가중치
MONTHLY_LOAN_WEIGHT = {
    1: 0.6, 2: 0.7, 3: 1.1, 4: 1.2, 5: 1.1, 6: 1.0,
    7: 0.8, 8: 0.8, 9: 1.0, 10: 1.1, 11: 1.2, 12: 1.4
}

# 월별 정기예금 신규 가중치
MONTHLY_DEPOSIT_WEIGHT = {
    1: 1.3, 2: 0.8, 3: 0.9, 4: 0.9, 5: 0.9, 6: 1.2,
    7: 0.8, 8: 0.8, 9: 0.9, 10: 1.0, 11: 1.1, 12: 1.4
}
```

## 3. 금리 변동과 데이터 연쇄 효과

### 3.1 기준금리 변동 시나리오

```
시나리오: 최근 2년간 기준금리 변동 이력

2024-01:  3.50%
2024-04:  3.50%  (동결)
2024-07:  3.25%  ▼ 인하 (경기 둔화)
2024-10:  3.00%  ▼ 인하
2025-01:  3.00%  (동결)
2025-04:  2.75%  ▼ 인하
2025-07:  2.75%  (동결)
2025-10:  3.00%  ▲ 인상 (인플레이션)
2026-01:  3.25%  ▲ 인상
```

### 3.2 금리 변동이 데이터에 미치는 영향

```
기준금리 인하 시:
  ├── 신규 대출 증가 (대출 수요↑)
  ├── 기존 변동금리 대출의 INT_RATE 하향 조정
  │   └── TB_LOAN_RATE_HIST에 변동 이력 추가
  ├── 정기예금 신규 감소 (금리 매력↓)
  ├── 정기예금 중도해지 증가 (더 낮은 금리로 재가입 방지)
  └── 주택담보대출 차환(갈아타기) 증가

기준금리 인상 시:
  ├── 신규 대출 감소 (대출 비용↑)
  ├── 기존 변동금리 대출의 INT_RATE 상향 조정
  ├── 연체율 증가 (이자 부담↑)
  ├── 정기예금 신규 증가 (금리 매력↑)
  │   └── 특히 1년 만기 정기예금 집중
  └── 적금 신규 증가
```

**시드 데이터 반영:**
- TB_LOAN_RATE_HIST: 변동금리 대출은 3~6개월 주기로 금리 변동 이력 생성
- 금리 인상기의 대출은 INT_RATE가 높고, 인하기의 대출은 낮게
- 같은 시기 실행된 대출이라도 신용등급에 따라 1~5%p 차이

## 4. 배치 처리와 데이터 생성 타이밍

### 4.1 일배치 스케줄

```
시간  | 배치 작업              | 영향 테이블
------|------------------------|---------------------------
01:00 | 전일 거래 마감 집계     | TB_DAILY_TXN_SUMMARY
02:00 | 고객 정보 동기화        | TB_CUST_INFO, TB_CUST_DETAIL
03:00 | 대출 원장 갱신          | TB_LOAN_INFO
03:30 | 연체 판정 배치          | TB_LOAN_OVERDUE, OVERDUE_YN 갱신
04:00 | 수신 원장 갱신          | TB_DEPOSIT_INFO
04:30 | 이자 계산 배치          | TB_DEPOSIT_INT_CALC
05:00 | 일별 잔액 스냅샷        | TB_LOAN_DAILY_BAL, TB_DEPOSIT_DAILY_BAL
05:30 | 고객 등급 재산정(분기말) | TB_CUST_GRADE_HIST
06:00 | 배치 완료, 일과 시작    |
```

### 4.2 월배치 스케줄

```
매월 1일 (전월말 기준):
  ├── TB_LOAN_OVERDUE_STAT:  전월 연체 통계 집계
  ├── TB_LOAN_MONTHLY_SUM:   전월 대출 월간 요약
  ├── TB_MONTHLY_TXN_SUMMARY: 전월 거래 월간 요약
  ├── TB_PROD_SALES_STAT:    전월 상품 판매실적
  └── TB_MGMT_INDEX:         전월 경영지표 산출

매 분기말+1일:
  ├── TB_CUST_GRADE_HIST:    고객 등급 재산정
  ├── TB_BIS_CAPITAL:        BIS비율 산출
  └── TB_PROVISION:          대손충당금 재산정
```

**시드 데이터 반영:**
- TB_LOAN_OVERDUE_STAT: 당월(현재 월) 데이터는 **없어야** 현실적
  (매월 1일에 전월분이 생성되므로)
- TB_CUST_GRADE_HIST: 등급 변동일이 분기말(3/31, 6/30, 9/30, 12/31)에 집중
- 일배치 데이터: 오늘자 데이터는 내일 새벽에 반영되므로 "오늘" 데이터는 아직 없을 수 있음

## 5. 이벤트 기반 데이터 생성 패턴

### 5.1 대출 실행 시 연쇄 생성되는 데이터

```
대출 1건 실행 시:
  1. TB_LOAN_INFO:          1행 INSERT (대출 원장)
  2. TB_LOAN_REPAY_SCHED:   N행 INSERT (상환 스케줄, 기간에 따라 12~60행)
  3. TB_LOAN_RATE_HIST:     1행 INSERT (최초 적용금리)
  4. TB_LOAN_EXEC_LOG:      1행 INSERT (실행 이벤트)
  5. TB_TRANSACTION:         1행 INSERT (대출금 입금 거래)
  6. TB_DEPOSIT_INFO:        잔액 UPDATE (대출금 입금으로 잔액 증가)

  담보대출인 경우 추가:
  7. TB_COLLATERAL:          1행 INSERT (담보 등록)
  8. TB_COLL_REAL_ESTATE:    1행 INSERT (부동산 담보 상세)
  9. TB_LOAN_COLLATERAL_MAP: 1행 INSERT (대출-담보 매핑)
```

### 5.2 연체 발생 시 연쇄 변경되는 데이터

```
연체 판정 시 (일배치 03:30):
  1. TB_LOAN_INFO:           OVERDUE_YN → 'Y', OVERDUE_DAYS 갱신, OVERDUE_AMT 갱신
  2. TB_LOAN_OVERDUE:        1행 INSERT 또는 UPDATE (연체 상세)
  3. TB_CREDIT_SCORE:        신용점수 하향 (다음 평가 시)
  4. TB_PUSH_NOTIFICATION:   1행 INSERT (연체 알림 발송)

  장기연체(30일+) 전환 시 추가:
  5. TB_LOAN_OVERDUE.독촉단계 갱신
  6. TB_CREDIT_WATCH:        1행 INSERT (신용감시 등록)
```

### 5.3 고객 신규 가입 시 연쇄 생성되는 데이터

```
고객 1명 신규 등록 시:
  1. TB_CUST_INFO:           1행 INSERT (기본 정보)
  2. TB_CUST_DETAIL:         1행 INSERT (상세 정보)
  3. TB_CUST_CONTACT:        1~2행 INSERT (연락처)
  4. TB_CUST_CONSENT:        3행 INSERT (개인정보수집, 제3자제공, 마케팅 동의)
  5. TB_CUST_AML:            1행 INSERT (CDD 수행 결과)
  6. TB_DEPOSIT_INFO:         1행 INSERT (보통예금 계좌 자동 개설)
  7. TB_EBANK_USER:          1행 INSERT (전자금융 가입 — 모바일뱅킹)

  → 고객 등록일, 계좌 개설일, 전자금융 가입일이 동일해야 정합적
```
