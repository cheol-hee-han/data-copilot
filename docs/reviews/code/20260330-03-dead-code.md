## Z-01. (유지보수성) context_explorer.py 레거시 함수 4개 미호출

### 위치
- `src/agents/nodes/reason/context_explorer.py:1019-1084` 부근

### 문제 상세

다음 4개 함수가 `context_explorer_node()` 메인 루프에서 **어디에서도 호출되지 않는다**:

```python
def _run_table_comparison(candidates, *, system_prompt) -> list[dict]:
    """후보 테이블 그룹 비교를 위해 별도 LLM 호출."""
    ...

def _find_comparison_groups(candidates) -> list[list[CandidateTable]]:
    """유사 테이블을 비교 그룹으로 묶는다."""
    ...

def _group_by_keyword(candidates) -> dict[str, list[CandidateTable]]:
    """테이블명의 키워드로 그룹핑."""
    ...

def _group_by_prefix(candidates) -> dict[str, list[CandidateTable]]:
    """테이블명의 접두사로 그룹핑."""
    ...
```

현재 Phase 5의 테이블 비교/제거 로직은 `_interpret_batch()` 내부의 `batch_result.rejected`를 통해 처리된다. `_run_table_comparison`은 **별도 LLM 호출로 비교 판정하는 레거시 방식**으로, 배치 해석 방식으로 리팩토링되면서 사용되지 않게 된 것으로 보인다.

**위험**: 1,171줄 파일에서 ~70줄의 죽은 코드가 가독성을 저하시키고, 코드 리뷰/리팩토링 시 혼란을 유발한다. 새 개발자가 이 함수를 사용하려고 시도할 수 있다.

### 해결 방안

**옵션 A (권장)**: 즉시 삭제

```bash
# 4개 함수와 관련 import를 제거
# _run_table_comparison, _find_comparison_groups, _group_by_keyword, _group_by_prefix
```

git history에 남아있으므로 향후 필요하면 복원 가능하다.

**옵션 B**: 향후 사용 계획이 있다면 별도 모듈로 분리하고 `# TODO: Phase 5 개선 시 활성화 예정` 주석을 추가

> Critical C-02와 동일 이슈. `20260330-01-critical-issues.md#C-02` 참조.

## Z-04. (유지보수성) _emit_progress 호출 경로 불명확

### 위치
- `src/agents/graph/runner.py:90-117` — 함수 정의부

### 문제 상세

`_emit_progress` 함수가 `runner.py`에 정의되어 있다:

```python
async def _emit_progress(on_event, node_name, action, explore_count=None):
    """WebSocket 이벤트로 진행 상황을 전송한다."""
    if not on_event:
        return
    ...
```

그러나 `run_pipeline()` 함수 본문에서 이 함수를 **직접 호출하는 코드가 보이지 않는다**. `tracker.on_node_event = on_event` (line 150)를 통해 tracker 내부에서 간접 호출되는 것으로 추정되지만, 이 관계가 코드상 명확하지 않다.

**위험**: 함수가 실제로 미사용이라면 죽은 코드이고, 간접 호출이라면 추적이 어려워 유지보수 시 실수로 삭제될 수 있다.

### 해결 방안

**실제 호출되는 경우**: 호출 경로를 docstring에 명시한다.

```python
async def _emit_progress(on_event, node_name, action, explore_count=None):
    """WebSocket 이벤트로 진행 상황을 전송한다.

    Note:
        이 함수는 EvaluationTracker.on_node_start/on_node_end 콜백에서 간접 호출된다.
        runner.py:150에서 tracker.on_node_event에 on_event를 바인딩하면,
        tracker가 각 노드 시작/완료 시 이 함수를 호출한다.
    """
```

**실제 미사용인 경우**: 제거한다.
